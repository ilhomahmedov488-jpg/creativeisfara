# Backend Creative Studio

Python 3.12, Django 5.2 LTS, Django REST Framework, PostgreSQL 16. События рассчитываются в `Asia/Dushanbe`, деньги — Decimal в TJS. Языковые поля `*_tg` и `*_ru` выбирает frontend, таджикский — основной.

## Локальный запуск

Из корня репозитория:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
cp .env.example .env
python -c 'import secrets; print(secrets.token_urlsafe(60))'
```

Вставьте сгенерированное значение в `SECRET_KEY` внутри `.env`. Для разработки оставьте `DEBUG=true` и пустой `DATABASE_URL`. Введите Payom URL/token/sender из своего кабинета. Без них запрос SMS даст 503, обхода входа нет.

```bash
python backend/manage.py migrate
python backend/manage.py runserver 127.0.0.1:8000
```

`/health/` проверяет приложение и базу. `runserver` только для разработки. Миграции один раз добавляют 9 участников, прайс и FAQ. Последующие запуски не сбрасывают цены. Заказов, видео, фотографий и выдуманных отзывов в исходниках нет.

## Номера команды

В локальном, исключённом из Git файле `private/team-phones.json` создайте JSON-объект: ключ — slug участника, значение — номер `+992` и 9 цифр. Slug: `abdu`, `ilhom`, `amri`, `muhammad`, `sadr`, `farrukh`, `muhi`, `abdul`, `muhammadjon`.

```bash
python backend/manage.py import_team_phones private/team-phones.json
```

Одинаковые привязки можно импортировать повторно, для изменения нужен `--replace`. Команда не печатает номера. На сервер передавайте файл отдельно от Git, после импорта удаляйте, копию храните приватно.

Абдумачид (`abdu`) — `admin`, Илхомиддин (`ilhom`) — `owner`, права одинаковые. Остальные — `employee`. Номер вне списка получает `client`. Смена привязки отзывает права старого номера при следующем запросе, даже в открытой сессии; профиль, видео и назначения сохраняются у участника. Свой номер меняет второй администратор. Для обслуживания доступна команда `createsuperuser`; пароль не используется в публичном SMS-входе, Django admin не открыт.

## Вход с frontend

Frontend и API должны быть на одном origin. Сессия в HttpOnly / SameSite=Lax cookie, в production — HTTPS. CORS закрыт, токены в localStorage не нужны.

1. `GET /api/auth/csrf/`: сохранить `csrfToken` из JSON.
2. `POST /api/auth/request-code/`: `{"phone":"НОМЕР"}` и заголовок `X-CSRFToken`. Ответ: `challenge_id`, `expires_in:300`. Код в ответе отсутствует.
3. `POST /api/auth/verify-code/`: `{"challenge_id":"UUID","code":"SMS-КОД"}`. Ответ: `role`, `cabinet`, `member` и **новый** `csrfToken`, который нужно использовать дальше.
4. `GET /api/me/`: восстановить кабинет после перезагрузки.
5. `POST /api/auth/logout/`: выйти.

При fetch передавайте cookies (`credentials:'same-origin'`), JSON и `X-CSRFToken` для изменений. Для файлов используйте FormData без ручного Content-Type. CSRF обязателен также для анонимного запроса SMS и проверки кода.

OTP: 5 минут, 5 попыток, одноразовый. Новый запрос аннулирует старый код. Отправка раз в 60 секунд, максимум 5 за час на номер, 20 за час на IP. Проверка — 50 за час на IP. В базе HMAC кода и хеш IP, код/IP не сохраняются. `SMS_BACKEND=memory` разрешён только в тестах/разработке, код через HTTP не выдаётся.

## API

Списки заказов, видео, отзывов и FAQ: пагинация `count`, `next`, `previous`, `results`, 30 записей. Неизвестные входные поля запрещены. Ошибки: 400 данные, 403 доступ/session login, 404 чужой заказ, 409 занятость/устаревшая версия, 503 SMS.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/catalog/` | Публичный прайс с revision |
| `GET /api/team/` | Профили без номеров и служебных ролей |
| `GET /api/portfolio/?placement=reels&event=wedding&author=ID` | Публичные видео, фильтры необязательны |
| `GET /api/reviews/`, `/api/faq/` | Публичный контент |
| `GET /api/bookings/?date=YYYY-MM-DD` | Клиент: свои; сотрудник: назначенные; администрация: все |
| `POST /api/bookings/` | Создать клиентскую заявку |
| `GET /api/bookings/UUID/` | Заказ с учётом прав |
| `PATCH /api/bookings/UUID/` | Администрация: расписание, команда, статус, оплата |
| `POST /api/bookings/UUID/change-requests/` | Клиент: перенос/отмена |
| `POST /api/management/change-requests/ID/decision/` | Администрация: решение |
| `GET /api/management/availability/?date=YYYY-MM-DD` | Свободные и занятые участники, ID заказа |
| `PATCH /api/management/prices/` | Прайс с проверкой версии |
| `GET, PUT /api/management/bindings/` | Закрытые привязки: список/изменение |
| `DELETE /api/management/bindings/ID/` | Убрать привязку участника, ID участника |
| `GET, PATCH /api/me/profile/` | Свои биографии и фотография |
| `POST, PATCH, DELETE /api/portfolio/[ID/]` | Свои видео, администрация — все |
| `POST, PATCH, DELETE /api/reviews/[ID/]`, `/api/faq/[ID/]` | Администрация: контент |

Сотрудник видит дату/время, место и команду, без финансов, телефона/имени клиента и заметок. Клиент видит свои суммы, статус, изменения и таймер. Администрация видит все данные.

### Создание заявки

```json
{"event":"wedding","package":"standard","extras":["love_story"],"client_name":"Имя клиента","date":"2027-06-20","location":"Зал","client_note":"Комментарий"}
```

События: `wedding`, `love_story`, `foteha`. Свадебные пакеты: `standard`, `pro`, `premium`. Дополнения: `foteha_one`, `foteha_two`, `love_story`, `album`, `hall_screen`. Для отдельного Love Story пакет `love_story`, фотехакунон — `foteha_one`/`foteha_two`, extras пустой.

Клиент выбирает дату, цену рассчитывает сервер. Премиум включает `album` и `foteha_one` бесплатно. Два варианта фотехакунон одновременно запрещены; доплата за две камеры в Премиум не согласована, такой выбор отклоняется.

Подтверждение PATCH с актуальной `version` и ID из `/api/team/`:

```json
{"version":1,"status":"confirmed","wedding_time":"19:00","paid_amount":"800.00","crew":[{"member":3,"duty":"operator"},{"member":7,"duty":"photographer"}]}
```

Стандарт/Про начинают за 6 часов до свадьбы, Премиум — в 12:00. Окончание = начало свадьбы +3 часа согласно рабочему брифу. Для отдельных съёмок администрация задаёт `shoot_start`, необязательно `shoot_end`, в ISO 8601 с зоной, например `2027-06-20T14:00:00+05:00`.

Подтверждение требует полного состава пакета; один человек занимает одну позицию. Заявка без команды не блокирует сотрудников. Любое сохранённое назначение резервирует весь день, при переходе через полночь — соседние дни. Снятие назначения, отмена и перенос освобождают прежние дни. Число свадеб в день не ограничено.

Транзакции блокируют заказ/участников в одинаковом порядке, уникальный индекс `(member, day)` защищает PostgreSQL от двойного назначения. Конфликт откатывает всё изменение. `version` защищает от записи из устаревшей вкладки.

Таймер: `countdown_seconds` у подтверждённого заказа, до начала съёмки. Живой frontend-таймер рассчитывается по `shoot_start` и `server_time`, минимум 0, с периодической синхронизацией. Статусы: `new → confirmed → editing → ready`; первые три можно отменить. Завершённые/отменённые не перепланируются. `paid_amount` вручную отмечается администрацией от 0 до стоимости, онлайн-оплаты нет. Предоплата в quote — 20%.

### Прайс и индивидуальная стоимость

```json
{"items":[{"code":"standard","price":"4500.00","revision":1}]}
```

Это тело PATCH `/api/management/prices/`. Обновление атомарное, revision увеличивается. Заказы сохраняют снимки прежних цен. До подтверждения администратор может явно пересчитать `package`/`extras`: применится текущий прайс, прежняя индивидуальная корректировка сбросится.

Для индивидуального Love Story, транспорта или скидки PATCH заказа принимает `adjustment` и `adjustment_reason`, например `{"version":1,"adjustment":"500.00","adjustment_reason":"Индивидуальный формат"}`. Это замена корректировки относительно суммы строк, не повторное прибавление. Меняется итог/20% заказа, каталог не меняется. Изменения денег, статусов, команды и привязок записываются в закрытый аудит.

### Перенос/отмена

Клиент: `{"kind":"reschedule","requested_date":"2027-06-25","reason":"Причина"}`, необязательно `requested_time`. До исходной даты начала съёмки должно быть не менее 15 календарных дней. Отмена: `{"kind":"cancel","reason":"Позвоните мне"}` не отменяет автоматически. Возможен один ожидающий запрос.

Решение: `{"version":2,"approve":true,"note":"Согласовано по телефону"}`, при переносе можно указать заменяющую `crew`. Конфликт сохраняет прежнее расписание, запрос остаётся pending. Отказ: `approve:false`. Условия отмены/возврата обсуждаются по телефону, списаний нет.

### Медиа/отзывы

Видео multipart: `title_ru`, `title_tg`, `event`, `placement` (`reels`/`portfolio`), `video`, `permission_confirmed:true`. Автор — текущий участник, публикация сразу видна. Сотрудник изменяет/удаляет своё, администрация — всё.

MP4/WebM до 200 МБ проверяются по расширению/сигнатуре. Полного декодирования/транскодирования нет: подготовьте ролики для телефона до загрузки. Фото до 10 МБ/20 мегапикселей уменьшается до 1600 px, сохраняется JPEG без исходных метаданных. Имена файлов — UUID.

`/media/` публичен: приватные свадебные материалы туда не загружать. Отзывы создаёт администрация, публикация требует `consent:true` и `published:true`. Имена/должности/опыт команды заданы миграцией; сотрудник меняет только биографию/фото.

## SMS

Payom HTTPS POST на предоставленный сервисом `/api/message`: Bearer token, `telephone`, `text`, `senderName`, `type=SMS`. Настройки только на сервере, redirects запрещены, timeout ограничен. Уточните точную схему ответа при подключении: публичная документация не описывает delivery receipts. HTTP success без явного отказа означает принятие провайдером, не подтверждение доставки.

```bash
python backend/manage.py dispatch_notifications --loop --interval 30
```

Напоминание — в 09:00 предыдущего дня по Душанбе, при позднем подтверждении в предыдущий день — ближайшим проходом worker. В день съёмки просроченное «завтра» не отправляется. Готовность — при `ready`. Перенос отменяет старое напоминание, отмена блокирует отправку. SMS на таджикском.

Очередь в базе: 5 попыток с увеличением интервала, ошибки `failed`/`error_code` смотрит обслуживающий администратор. Токен/ответ провайдера не логируются. Уникальный ключ не даёт повторно создавать уведомление. При аварии после принятия SMS провайдером до фиксации транзакции возможен повтор: Payom пока не предоставил контракт идемпотентности. Запускайте один worker.

Раз в день: `python backend/manage.py purge_expired_auth` удаляет старые OTP/счётчики/сессии. WhatsApp/Telegram для администрации не подключены, способ интеграции ещё не выбран.

## Docker/production

Размещение и покупка услуг не выполнены. Production `.env`: `DEBUG=false`, случайный SECRET_KEY, настоящие ALLOWED_HOSTS и `CSRF_TRUSTED_ORIGINS=https://ВАШ_ДОМЕН`. PostgreSQL DATABASE_URL обязателен. Payom URL/token/sender; тестовый SMS backend запрещён. Для Compose добавьте POSTGRES_PASSWORD — случайные буквы/цифры без символов URL.

```bash
docker compose up -d db
docker compose build
docker compose run --rm app python manage.py migrate
docker compose up -d app worker
```

API слушает только `127.0.0.1:8000`, база наружу не открыта. В Caddyfile.example замените домен/настройте HTTPS. Только за доверенным proxy, который перезаписывает входные заголовки, включите `TRUST_PROXY_HTTPS=true`, `TRUST_CLIENT_IP_HEADER=true`. Прямой внешний доступ к приложению должен быть закрыт. Иначе оставьте false.

Медиа в volume media_data: подключите Caddy на чтение в `/srv/creative-media` или измените путь. Не отдавайте `.env`, private, SQLite или корень проекта веб-сервером. Контейнер работает от непривилегированного пользователя. С production-настройками выполните `python backend/manage.py check --deploy`.

Копируйте PostgreSQL/media ежедневно вне сервера и перед миграциями, проверяйте восстановление. Следите за местом: лимит ролика не ограничивает суммарный объём. CDN, облачное хранение, транскодирование и интерфейс мониторинга пока не подключены.

Следующий этап: frontend с API, проверка настоящего Payom и полного сценария на выбранном сервере.
