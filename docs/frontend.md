# Рабочий сайт: первый шаг

Frontend подключён к Django API. Django отдаёт страницу и API с одного адреса; это нужно для защищённого входа по SMS и серверной сессии. Node.js нужен только разработчику для проверок. Отдельная сборка frontend не требуется.

GitHub Pages по-прежнему показывает макет. Он не выполняет бронирования и не запускает Python. Чтобы увидеть рабочую версию, запустите приложение по инструкции ниже. На этом этапе сервер и домен не покупаются.

## Запуск на Windows

Откройте PowerShell в папке репозитория. Нужен Python 3.12.

1. Обновите код после слияния запроса в GitHub:

   ```powershell
   git switch main
   git pull
   ```

   Для проверки до слияния вместо этого выполните `git fetch origin` и `git switch --track origin/frontend/live-api`. Если ветка уже есть локально: `git switch frontend/live-api`, затем `git pull`.

2. Создайте окружение и установите зависимости:

   ```powershell
   py -3.12 -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
   ```

3. Если `.env` ещё нет, выполните `Copy-Item .env.example .env`. Существующий файл не заменяйте. Сгенерируйте ключ:

   ```powershell
   .\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(60))"
   ```

   Откройте `.env` в редакторе и вставьте значение после `SECRET_KEY=`. Для локального запуска оставьте `DEBUG=true`, `ALLOWED_HOSTS=localhost,127.0.0.1` и пустой `DATABASE_URL=`. Ключи и этот файл не загружайте в GitHub.

4. Для SMS заполните `PAYOM_URL`, `PAYOM_TOKEN`, `PAYOM_SENDER` реквизитами Payom. Адрес должен быть HTTPS и вести на API отправки сообщений. `SMS_BACKEND=payom`. Без настроек публичные страницы доступны, но отправка кода вернёт ошибку сервиса; вымышленных успешных отправок нет.

5. Подготовьте базу и запустите сайт:

   ```powershell
   .\.venv\Scripts\python.exe backend/manage.py migrate
   .\.venv\Scripts\python.exe backend/manage.py runserver 127.0.0.1:8000
   ```

6. Откройте **http://127.0.0.1:8000/**. Терминал оставьте открытым. Для остановки нажмите Ctrl+C. Это запуск на компьютере для разработки, не публикация для клиентов.

На Linux/macOS команды те же, но интерпретатор окружения — `.venv/bin/python`; первоначальное создание — `python3 -m venv .venv`.

## Подключение аккаунтов команды

База создаётся с девятью профилями и прайсом, без личных номеров. Перед входом команды импортируйте приватный файл, как описано в [backend.md](backend.md#номера-команды):

```powershell
.\.venv\Scripts\python.exe backend/manage.py import_team_phones private/team-phones.json
```

Файл с номерами хранится отдельно от Git. Участник подтверждает свой номер настоящим одноразовым кодом, и сервер определяет кабинет. Назначить себе роль через интерфейс нельзя. Непривязанный номер открывает кабинет клиента.

## Что проверить после подключения Payom

| Действие | Ожидаемый результат |
| --- | --- |
| Выбрать язык, открыть главную и прайс | Таджикский по умолчанию; реальные цены из базы; пустые работы и отзывы до их загрузки |
| Выбрать пакет и дополнительные услуги, затем войти | Форма сохраняется до отправки; Премиум включает альбом и фотехакунон с одной камерой |
| Подтвердить клиентский номер и отправить заявку | Новый заказ появляется в своём кабинете и у администрации |
| Войти Илхомиддину или Абдумаҷиду | Открывается кабинет управления со всеми заказами, прайсом и командой |
| Назначить оператора на свадьбу | На эту дату он занят; на другую свадьбу выбираются другие сотрудники |
| Изменить прайс | Новые заявки используют новую цену, существующие сохраняют расчёт |
| Подтвердить дату, время и полный состав | Клиент видит таймер до начала съёмки по времени Душанбе |
| Войти сотруднику | Только назначенные ему съёмки без финансов и телефона клиента; собственные видео и профиль |
| Загрузить разрешённый ролик/Reels | Появляется в портфолио сразу; автор определяется сервером |
| Отправить запрос отмены/переноса | Появляется запрос для решения администрации, без автоматической отмены |
| Выйти и обновить страницу | Приватный кабинет требует нового входа |

Напоминания и сообщение о готовности отправляет отдельный worker. Во втором терминале запустите:

```powershell
.\.venv\Scripts\python.exe backend/manage.py dispatch_notifications --loop --interval 30
```

Один только открытый сайт SMS-напоминания не отправляет. Часовой пояс — Душанбе; онлайн-оплаты нет.

## Проверки разработчика

Нужен Node.js 24 для тестов интерфейса:

```bash
npm --prefix frontend ci
npm --prefix frontend test
python backend/manage.py test studio --settings=config.test_settings
python backend/manage.py check --settings=config.test_settings
python backend/manage.py makemigrations --check --dry-run --settings=config.test_settings
python backend/manage.py collectstatic --noinput --settings=config.test_settings
```

Тесты интерфейса проверяют DOM и HTTP-запросы в jsdom; это не визуальная проверка в браузере или отправка настоящих SMS. Серверные тесты используют изолированную базу и тестовую SMS-очередь. GitHub Actions также проверяет PostgreSQL и одновременное назначение сотрудников двумя администраторами.

## Подготовка к серверу

В Docker frontend копируется в образ вместе с backend. После сборки и миграций выполните `docker compose run --rm app python manage.py collectstatic --noinput`. Статика сохраняется в `static_data`, медиа — в `media_data`. В примере Caddy они читаются из `/srv/creative-static` и `/srv/creative-media`: на выбранном сервере потребуется настроить эти подключения или изменить пути.

HTTPS, PostgreSQL, настоящие ключи Payom, резервные копии и защищённые настройки описаны в [backend.md](backend.md#dockerproduction). Проверка реального SMS, браузеров телефона и полного сценария после размещения ещё предстоит. WhatsApp/Telegram и точная точка на карте пока не подключены.
