# Creative Studio Isfara

Сайт команды свадебной видеосъёмки Creative Studio Isfara.

В репозитории находятся согласованные макеты, frontend с подключением к API и backend на Django 5.2 LTS / Django REST Framework. Рабочая версия запускается одним приложением Django. На GitHub Pages опубликован отдельный демонстрационный дизайн; рабочий сервер пока не размещён.

## Что уже подготовлено

- Светлый дизайн для телефона, таджикский и русский языки.
- Публичные страницы, свадебные пакеты, дополнительные услуги и пример кабинета клиента.
- Отдельные кабинеты Илхомиддина и Абдумачида с одинаковыми полными правами.
- Кабинеты семи сотрудников: личное расписание, свои видео и профиль.
- Редактирование прайса с сохранением прежних цен в существующих заказах.
- Несколько свадеб на одну дату с проверкой занятости каждого сотрудника.
- Серверная привязка телефона к участнику команды и автоматический выбор кабинета после подтверждения номера.

## Как работает демонстрация

В макетах используются вымышленные заказы с пометкой DEMO. Изменения хранятся в памяти страницы и исчезают после перезагрузки. Реальные сообщения, платежи, бронирования и загрузка на сервер не выполняются.

Демонстрационный код входа — `123456`. Переключатель аккаунтов нужен только для просмотра дизайна. В рабочем сайте вход и права будут проверяться сервером после настоящего SMS-кода.

Личные номера сотрудников для входа не включены в репозиторий. В копии макета список привязок пустой: демонстрационные номера можно добавить через кабинет управления. В рабочем приложении привязки хранятся в закрытой базе данных.

## Предпросмотр на GitHub Pages

Публичный предпросмотр содержит дизайн сайта и кабинетов с демонстрационными данными. Backend и настоящие SMS к нему не подключены. GitHub Actions публикует только специально собранные HTML/CSS из `preview-dist`, без базы, backend, личных номеров и ключей.

Однократно включите **Settings → Pages → Source: GitHub Actions**. Затем workflow **Design preview on GitHub Pages** публикует изменения дизайна при обновлении `main`; его также можно запустить через **Actions → Run workflow**. Адрес публикации будет показан в Settings → Pages и в завершившемся workflow. До успешного deployment ссылка не считается активной.

Локальная сборка: `python scripts/build_preview.py`; откройте `preview-dist/index.html`. Исходники согласованных макетов остаются в `design/`.

## Серверная часть

Код находится в `backend/`, инструкция — [docs/backend.md](docs/backend.md). Реализованы вход по одноразовым SMS-кодам, роли, бронирования, снимки цен заказа, назначения сотрудников, перенос и отмена, свои видео, отзывы и FAQ. SMS отправляет отдельный worker. Для Payom нужны ваши адрес API, токен и имя отправителя.

Личные номера и ключи в Git не включены. Backend не использует демонстрационный код из макетов. Production требует PostgreSQL. `compose.yaml` содержит приложение, PostgreSQL и worker; GitHub Actions запускает проверки с PostgreSQL, включая одновременное назначение сотрудника двумя администраторами.

## Рабочий сайт

Инструкция: [docs/frontend.md](docs/frontend.md). Откройте `http://127.0.0.1:8000/` после запуска Django. Главная, работы, цены, бронь и все кабинеты используют API этого же сервера. Изменение считается успешным только после ответа API; входных кодов и переключателя ролей в рабочем интерфейсе нет. При перезагрузке кабинет восстанавливается через серверную сессию. Локально сохраняется только выбранный язык.

Остаётся подключить и проверить настоящий Payom, выбрать сервер, домен и медиахранилище, разместить приложение с HTTPS и проверить его с телефона. Фотографии команды, разрешённые ролики, отзывы и точный адрес ещё нужно добавить. Уведомления администрации в WhatsApp/Telegram пока не подключены: способ интеграции ещё не выбран.
